## 本轮修复

1. 前端默认 API 改为同源，增加开发代理；解决宿主机 8066 没有监听导致的连接失败。
2. 后端原系统模型与 Embedding 密钥为占位值。复用已有提供商配置，系统模型设为 gpt-5.1，Embedding 设为实测可用的 text-embedding-3-small / 1024 维。实际密钥只在本机忽略的 Docker `.env` 中，不写入前端或本记录。
3. 缓存失效延后到外层数据库事务提交后，避免 MQ 修改尚未提交时，查询又将旧值写回缓存。实测发现的广场删除旧缓存问题已复测通过。增加提交、回滚、无事务三个回归测试。
4. 发布智能体时，新模板使用已分配的 templateId，避免智能体和模板 ID 不一致，导致重复发布创建多个条目。
5. 会话创建只接受 chat/work，拒绝无效类型。
6. 管理页面配置筛选参数由错误的 clientId 改为契约中的 keyword；该项为静态契约修复，没有使用普通账号绕过管理权限实测。
7. 后端 Surefire 使用 Spring Boot 管理的版本并启用测试，确保 JUnit 5 回归实际执行。

在 `frontend` 目录运行可重复的真实冒烟测试：

```powershell
$env:LIVE_USER = '<测试账号>'
$env:LIVE_PASSWORD = '<该账号密码>'
npm run test:live
Remove-Item Env:LIVE_PASSWORD, Env:LIVE_USER
```

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| LIVE_API_ROOT | 默认 `http://127.0.0.1:5180/miniagent/api/v1` |
| LIVE_CLIENT_ID | 选用的真实聊天客户端；不设置时使用首个可用客户端 |
| LIVE_RAG_TAG / LIVE_RAG_QUESTION / LIVE_RAG_EXPECTED | 已有知识库标签、问题与期望答案片段，三项一起设置以验证检索 |
| LIVE_AGENT_ID | 校验已有智能体详情 |
| LIVE_WORK_PROMPT / LIVE_WORK_EXPECTED | 与 LIVE_AGENT_ID 一起设置，执行指定任务并校验最终答案；请选择无外部副作用的测试任务 |
| LIVE_REPORT | 可选 JSON 结果输出路径，不含凭据和模型配置 |

脚本会调用真实模型，创建并清理自己的临时会话；每种类型需留有一个会话空位（后端每类最多 3 个）。它不创建模型凭据或智能体，不发布内容，也不上传新的知识文档。详细实测所用的本地临时脚本位于工作区 `.tmp/`，正式可复用入口为 `scripts/live-integration.mjs`。

## 2. 开发约定（必须遵守，全部来自现有代码，不是我的偏好）

1. **一律走 `app/lib/api.js` 的出入口**：`post(path, { json | query | form | signal })`、`stream(path, json, onEvent, signal)`。
   注意 `api.js:14` 的 `method` **恒为 `POST`** —— 这是设计（后端 130 个端点确实是 POST）。新增 GET 端点时必须走 Office 那套（见第 3 条），不要自己写 `fetch`。
2. **路径写法**：传「`/api/v1` 之后的后缀」，如 `post("/workspace/plaza/page")`；前缀由 `api.js:3` 统一拼。不要自己拼 `/miniagent`。
3. **Office 子系统**：只能用 `app/lib/office-api.js`。它显式指定 HTTP 动词（`:36` 默认 `GET`）、传 `Idempotency-Key`（`:42`）、并强制 URL 必须落在 `<root>/office/` 下（`safeOfficeUrl`，`:16-22`）。后端 `POST /office/runs` 与 `POST /office/artifacts/{id}/revisions` 的 `Idempotency-Key` 是**必填**，漏了直接 400。
4. **错误处理**：`post()` 内部已 `checkResponse` 抛 `ApiError`；组件里用 `report(e)`（`workspace.js` 导出）统一提示，不要 `console.log` 了事。
5. **管理中心表单**：字段定义只改 `app/lib/admin-schema.json`；页面会自动渲染。`Admin.vue:27` 会把以 `origin` 开头的字段从「用户可填」里过滤掉、只在更新时回填，**不要把它们当成普通输入框**。
6. **分页**：`PlazaPageDTO` 的 `pageSize` 有 `@Max(10)`（`PlazaPageDTO.java`），广场当前用 9、管理中心用 10，别调大。
7. **SSE 解析**：统一用 `app/lib/protocol.js` 的 `createSSEParser` / `consumeSSE`，不要另写解析器。
8. **不要动旧前端** `frontend/src/**`；需要参考实现时只读。

## 3. 三个非接口类风险（写代码时会撞上）

### 3.1 `/ai/chat/stream` 的 SSE 帧格式（**已实测通过，2026-10-26**）

- 后端：`AiController.java:244` 只有 `@PostMapping("/chat/stream")`，**没有声明 `produces`**，返回 `Flux<String>`（元素是模型原始 token）。
- 前端：`protocol.js:57` 硬校验 `content-type` 必须包含 `text/event-stream`；解析器只认 `data:` 行。
- 风险：若协商成 `text/plain` → 前端直接抛「服务未返回 SSE 数据」；若协商成 event-stream 但元素不带 `data:` 前缀 → 对话区「空回」。
- **实测结论（2026-10-26，真后端）**：`Accept: text/event-stream` 请求返回 `content-type: text/event-stream`，正文首字节为 `data:`（实测响应 58 字节）→ Spring MVC 确实把 `Flux<String>` 按 SSE 帧写出，`protocol.js` 的 `consumeSSE` 可正常解析。**风险关闭。**
- 复验命令：`curl -s -m 6 -X POST -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -H "Accept: text/event-stream" -d '{"clientId":"no_such_client","sessionId":"x","userMessage":"hi"}' http://127.0.0.1:8066/miniagent/api/v1/ai/chat/stream -o sse.bin -w '%{content_type} %{size_download}\n'; head -c 60 sse.bin`。注意这是 `clientId` 无效时的早退分支，验证的是**帧格式**；真实模型流的 token 内容仍需一次带真实 clientId 的调用确认。

### 3.2 Office 能力依赖环境变量才存在

- `application.yml:9` 默认 `zflow.office.enabled=false`；`OfficeController.java:26` 是 `@ConditionalOnProperty(havingValue="true")`。
- 当前容器里 `ZFLOW_OFFICE_ENABLED=true`（我实测 `printenv`），所以 13 个端点活着；**用裸 `java -jar` 起就会全部 404**，前端「智能办公」整页失效。
- 前端要做的是：`useOfficeWorkspace` 初始化失败时给明确空态（而不是白屏），并在控制台提示「后端未开启 Office 能力」。

### 3.3 未登录即演示模式

- `workspace.js:11` `isDemo = computed(() => !state.auth)`；`:65` 在 demo 下**直接返回假数据、一个请求都不发**；全仓 23 处 `isDemo.value ?` 分支（`Agents/Plaza/Schedules/Settings/Conversation`）。
- 含义：**未登录时"功能看起来都在"是 `demo.js` 撑的**，任何新功能都必须同时补「真实分支」和「demo 分支」，否则未登录环境下会报错或空白。
- 联调前请用真实账号登录，不要用未登录状态判断接口是否通。

### 8.3 新发现①：`agent.modelId` 前后端必填不一致（已修）

- 现象：库列 `ai_agent.model_id` 是 **NOT NULL**，但 `admin-schema.json` 里 `agent.modelId` 是 `required: false` → 管理员不填模型直接保存，后端抛 `Column 'model_id' cannot be null`，前端只显示「系统异常，请联系管理员处理」（已实测复现，后端日志 `Cause:` 明确）。
- 修复：`admin-schema.json` 的 `agent.modelId` 改为 `required: true`（`npm run build` 通过）。因为 `Admin.vue:76` 已加载 `/admin/list/modelId` 字典，该字段会自动渲染成下拉（实测字典 3 个模型），不必手输。
- 真机验证：带 `modelId` 调 `agent/insert` → code=200；`agent/delete` → code=200，agent 数 1→2→1。

### 8.4 新发现②：`ai_flow` 的唯一键是 `(agent_id, client_role)`，不是 `(agent_id, client_id)`

- 同一 agent 下**不能有两个 client 承担同一 `clientRole`**；冲突时后端返回 HTTP 200 + `code=500`「数据已存在，请修改后重新添加」。
- 对前端的影响：flow 新增/编辑被拒时必须在弹窗里显示该文案（`save()` 的 `catch → error.value` 已满足）；UI 上最好提示「同一智能体的角色不可重复」。

### 8.5 数据操作提示

- 本机把**长中文 SQL 通过文件管道喂 `mysql` 会挂住**（多次 2 分钟级超时），改用 `docker exec ... mysql -e "SQL"` 或走后端 API 写入即可。
- 联调时删数据前务必确认选择器：`/admin/flow/delete` 的参数是 `(agentId, clientId)`，但唯一键是 `(agent_id, client_role)`，两者不一致容易误删（本次联调就误删过一条 planner 行，已用 API 重建）。
